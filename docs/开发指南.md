# 开发指南

## 分层

`catalog` 读取书籍配置，`presets` 递归合并预设和书籍覆盖规则，`plugins` 选择解析器。解析器返回 `ParseResult(questions, issues)`；`pipeline` 统一应用勘误、检查源页和题目、生成报告，最后由 `export` 输出原生 Excel。

桌面面板通过子进程调用 CLI。新增功能先放入公共模块，再接入命令行；界面不另写解析和校验逻辑。

这是一个带本地资料的工作区工具，推荐 `pip install -e .` 可编辑安装。PDF、OCR、输出及虚拟环境不纳入 Git；代码和规则可以独立版本管理。原书文件不随工具发布。

## 新增书籍与插件

1. 运行 `init-book` 创建配置。
2. 选择接近书籍版式的预设，在 `rules` 中覆盖差异。
3. 先识别一个完整章节，确认题目与答案对应关系，再处理全书。
4. 需要额外处理时，复制 `plugins/example.py` 为 `plugins/mybook.py`，将配置中的 `plugin` 改为 `mybook`。

```python
from meowcannery.parsers.rule_based import parse as parse_rules

def parse(book, rules):
    result = parse_rules(book, rules)
    # 仅处理本书的特殊版式；保留每题的 source / section / number。
    return result
```

也可以完全自定义解析，返回 `meowcannery.plugins.ParseResult`。公共模块不需要添加书名判断。

第三方包可声明：

```toml
[project.entry-points."meowcannery.plugins"]
mybook = "my_package.parser:parse"
```

插件是本地 Python 代码，会在当前进程中执行；只安装自己维护或已审读的插件。

## 题目契约

必需字段：`stem`、`type`、`options`、`answer`、`chapter`。类型为“单选题 / 多选题 / 判断题 / 填空题 / 简答题”，非选择题的 `options` 为 `[]`。选择题答案是去重的 A–H 字母；判断答案统一为 `√` 或 `×`。

建议字段：`section`（小节 ID）、`number`（原题号）、`source`（`p0011.md`）、`answer_source`、`subject`、`explanation`。 `(chapter, section, number)` 必须唯一，避免同章选择题与计算题互相覆盖。

未知题型、无法可靠匹配的答案或 OCR 异常放进 `ParseResult.issues`，每条包含 `source` 和 `reason`，尽可能提供章节、小节和题号。不要吞掉错误或用推测答案填充。

## 规则覆盖

`rules/*.json` 使用 `extends` 继承预设。字典递归合并，标量和列表整体替换；循环继承或无效正则会报错。

```json
{
  "extends": "chapter_answers",
  "name": "我的复习指南",
  "description": "本书特殊小节标题",
  "quiz_start": "^(?:自测题|课后习题)$",
  "sections": {"案例分析": "discuss"}
}
```

书籍配置可使用相同的 `rules` 字段覆盖预设。`sections` 支持 `single/shared/multi/fill/judge/define/essay/calculate/discuss/translate/spectrum/essay_calculate`；医学连续选择题号使用 `choice_numbering: "continuous"`。整节只有一道无编号题时，使用 `unnumbered_sections: {"章节名称": ["essay"]}`。

题干与答案分别使用 `question_pattern` 和 `answer_pattern`：题干可能以数字、化合物编号开头，而答案续行中的小数不能误识成题号。HTML 表格保留行与单元格边界，避免数值列被当作新题。新增边界规则请补充涵盖读序、题号与答案对应关系的回归夹具。

`chapters` 按 **PDF 从 1 开始的物理页码**指定章节起点，例如 `{"9": "第一章 绪论"}`。`rules.page_ranges` 是包含首尾页的区间，例如 `[[11,12],[21,28]]`。页码范围应包括完整习题和答案，不能只选题目页。

通用规则的适用范围是章节式、编号习题。多栏读序、图片结构式、无编号答案及原书排版错误需要单独校核；预设不会凭题意纠错。

## 勘误

`corrections/<书籍配置名>/source.json` 对 OCR 原文逐处精确替换，格式：

```json
[{"page":"p0011.md","old":"待修正原文","new":"扫描页核对后的文字","reason":"PDF 第 11 页，OCR 漏字"}]
```

`questions.json` 在解析完成后按 `match` 唯一定位，并检查 `before`：

```json
[{"match":{"chapter":"第一章 绪论","section":"single","number":1},
  "before":{"answer":"A"},"after":{"answer":"B"},
  "reason":"已核对的勘误依据；仅为格式示例，不得未经依据使用"}]
```

所有书籍的勘误都位于 `corrections/<书籍配置名>/`（即 `books/<书籍配置名>.json` 的同名目录）。药理学勘误已迁入相同目录，并统一题目匹配格式。

## OCR 环境

基础安装不会自动安装体积很大的识别模型，也不会更换现有 GPU 驱动。当前使用的本地引擎为 `PaddleOCRVL(pipeline_version="v1.6")`，默认 150 dpi、每批 4 页。已有缓存可离线构建；首次加载模型可能需要网络下载。

新机器先依据 [PaddleOCR 官方安装说明](https://www.paddleocr.ai/latest/en/version3.x/installation.html) 安装与系统及 CUDA 匹配的 PaddlePaddle，再安装支持 VL 的 PaddleOCR。确认 `python -c "from paddleocr import PaddleOCRVL"` 能成功导入。

缓存 `manifest.json` 记录 PDF SHA-256、页数、分辨率和引擎。不同 PDF 或识别配置不能复用同一缓存目录。中断后再次运行相同命令继续缺失页；不要把不同书籍放进同一 OCR 目录。

## 验证

核心测试使用小型 Markdown 夹具，不依赖 PDF、GPU 或模型。药理学全书回归验证此前已核实的 2165 题，需要本地 `data/ocr/yaoli`。

分析化学本地回归覆盖 899 道已解析题目的题号映射、补回的核素题、图片错位修复和待核对题目隔离。缺少本地资料时，两本书的集成测试会跳过。`原页核对.html` 由统一流程生成，展示待核对题目及相关原页；不把 OCR 识别结果自动认定为正确答案。

`tests/exameow150` 固定 Exameow **v1.5.0** 的官方导入源码，以实际 `parseExcel` 回读新生成的文件，并逐题核对题型、选项、答案、章节、学科和解析。运行方法见该目录的 README。测试不操作程序内已有题库或练习记录。
